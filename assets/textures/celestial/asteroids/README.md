# Asteroid Textures

Textures for asteroid bodies. The game deliberately uses a single shared
rock map for all non-Vesta asteroids rather than per-class PNGs — the
per-class color profile in `asteroid_class_profile` does the hue
differentiation on top of one neutral base, which keeps the dark side
legible under any lighting angle.

## Available Textures

- **Generic rock (used by every C/S/M/V/D/P/Unknown asteroid and by
  dwarf planets / moons that fall through to the generic fallback):**
  `generic_c_type_2k.jpg` — neutral grey rock with cratered relief.
- **`generic_s_type_2k.jpg`** — kept on disk for reference; the generic
  routing no longer points at it because its warm pink-brown splotches
  read as a Mars-like surface and crush the dark side into a
  black silhouette under back-lighting.
- **`vesta_4k.png`** — dedicated basaltic albedo for Vesta. Vesta is the
  only asteroid with a dedicated texture and bypasses the generic
  fallback.

## Spectral Type Mapping

The game uses these textures based on asteroid classification:
- **C-type:** Most common in outer main belt (~75% of asteroids).
  Multiplier `~0.55` over the neutral rock — keeps the rock its
  natural charcoal grey.
- **S-type:** Common in inner main belt (~17% of asteroids). Multiplier
  `~0.78` with a small warm bias — overlays warm grey on top of the
  neutral rock.
- **M-type:** Metal-rich asteroids (procedurally generated). Cool grey
  multiplier + raised `metallic` to suggest metal-silicate mix.
- **V-type:** Basaltic asteroids from Vesta family (uses Vesta
  texture when available; otherwise the generic rock + basaltic brown
  multiplier).

## Normal-map workflow

Asteroid and comet materials use two shared tangent-space relief maps that
ship in this folder:

- `generic_rock_normal_2k.png` — primary relief (craters, fractured
  regolith, faceted rock faces). Loaded as the material's
  `normal_map_texture` for every asteroid and comet. Bevy 0.18 does
  not expose a public `normal_map_strength` knob, so the relief reads
  at the default scale; the map is dense enough to be visible at
  in-game zoom.
- `generic_rock_roughness_2k.png` — single-channel roughness in the
  green channel (GLTF convention). Loaded as the material's
  `metallic_roughness_texture`; the per-class `metallic` value still
  drives the metallic reading, this map only adds micro-variation.

## Normal-map pool (per-body relief variety)

Asteroids pick one of four tangent-space normal-map variants per body
so each one reads as a distinct surface rather than one bump map
recoloured by the per-class tint. The selection is deterministic from
the body name (`hash(name) % 4`); comets fall through to the legacy
shared map above because icy nucleus relief reads better against the
lower-frequency legacy map. All four variants are **more cratery**
than `generic_rock_normal_2k.png`, which is now the fallback when the
pool is empty or a mod removes a variant.

| File                                | Character                                    | Real-world analogue              |
|-------------------------------------|----------------------------------------------|----------------------------------|
| `generic_rock_normal_a_2k.png`      | Heavily cratered, dense small/medium craters | Bennu / Ryugu / Callisto         |
| `generic_rock_normal_b_2k.png`      | Sparse large craters with central peaks      | Mathilde / Eros                  |
| `generic_rock_normal_c_2k.png`      | Fractured rock faces (linear ridges/breaks)  | Itokawa                          |
| `generic_rock_normal_d_2k.png`      | Rolling regolith, gentle low-frequency base  | Ceres / Vesta                    |
| `generic_rock_normal_2k.png` (fallback) | Sparse, low-frequency relief             | Legacy baseline                  |

The variants are generated by
`scripts/generate_rock_normal_variants.py` (see header for the recipe
pinned seeds and the per-variant crater counts). Each variant bakes
its own crater morphology — variant `a` packs ~42 craters with no
central peaks; variant `b` drops 7 large craters (all with central
rebound peaks because `r > 90 px`); variant `c` adds linear fracture
lines on top of 7 medium craters; variant `d` keeps a low-frequency
rolling base with 18 scattered craters. The new variants push the
relief gradient gain to 3.5 (was 2.5 in the legacy script) to
compensate for Bevy 0.18 not exposing `normal_map_strength` publicly.

Adding a new variant is a two-step canary-friendly change:

1. Drop the new PNG into this folder with the
   `generic_rock_normal_<x>_2k.png` naming.
2. Append the path to `ROCK_NORMAL_VARIANTS` in
   `src/plugins/solar_system.rs::pick_asteroid_rock_normal_path`.

The selector uses modulo indexing so a missing index falls back to
the legacy map rather than panicking; the project's load path is
defensive about absent optional assets already.

## Denser roughness (asteroid-only)

`generic_rock_roughness_dense_2k.png` is a sibling of the legacy
roughness map with an extra procedural fine-grain noise layer
(~4 px cells) added on top of the EXR-derived roughness. The band
stays inside `[0.85, 1.0]` so the per-class scalar still multiplies
into the same shader roughness range; the result is a touch more
gritty at close zoom. Asteroids use the dense variant; comets stay
on the legacy map (icy nuclei don't want rock-style micro-variation).
Generated by `scripts/bake_rock_roughness_dense.py` from the same
dark_rock_02 EXR source as the legacy map.

The class palette is intentionally subdued and mission-informed: Bennu and
Ryugu motivate charcoal, rugged C-types; Eros motivates muted grey/tan
S-types; Dawn's Vesta imagery motivates basaltic grey with albedo variation;
and Psyche observations motivate mixed grey rock/metal rather than a uniformly
shiny metallic surface. Per-name jitter is deterministic so save/load and new
runs produce the same appearance.
